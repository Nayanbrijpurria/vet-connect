## 10. Kotlin Coroutines and Performance Engineering

Coroutines must be used appropriately throughout the VetConnect Kotlin/Ktor backend.

### Core principles

1. Prefer Kotlin Coroutines and suspend functions for asynchronous backend operations.
2. Use `suspend` functions for database, network and service operations wherever supported by the existing architecture.
3. Use `Dispatchers.IO` for blocking I/O operations.
4. Use `Dispatchers.Default` for CPU-intensive operations such as data processing, calculations and computational tasks.
5. Avoid running CPU-intensive operations on the main request-processing thread.
6. Never use `Dispatchers.IO` as a default solution for CPU-intensive work.
7. Avoid unnecessary thread creation and excessive coroutine launching.
8. Use structured concurrency and appropriate coroutine scopes.
9. Avoid `GlobalScope`.
10. Handle coroutine cancellation and exceptions correctly.
11. Do not introduce unnecessary concurrency where sequential execution is safer or more efficient.
12. Use connection pooling and efficient database queries instead of creating unnecessary database connections.
13. Avoid blocking calls inside suspend functions.
14. Do not use `runBlocking` in normal production request-handling code.

### Ktor-specific requirements

- Use Ktor's coroutine-friendly request handling.
- Prefer suspend repository and service methods.
- Ensure database operations do not block request-processing threads.
- Use appropriate transaction management.
- Do not launch background coroutines without proper lifecycle management.
- Use bounded concurrency when processing multiple tasks.

### Performance and scalability

Before implementing a feature, consider:
- CPU utilisation
- Memory consumption
- Database connection usage
- Number of concurrent requests
- Response time
- Scalability under multiple users

Do not introduce coroutines just for the sake of using them. Choose the correct execution strategy based on whether the task is CPU-intensive, I/O-intensive or a combination of both.

### Important implementation rule

Before modifying existing code, inspect its current coroutine usage and architecture. Preserve working functionality and avoid unnecessary rewrites.

The goal is to build a responsive, efficient, scalable and production-ready Kotlin/Ktor backend.
